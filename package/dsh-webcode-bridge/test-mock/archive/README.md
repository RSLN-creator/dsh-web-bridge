# test-mock/archive/ — 一次性探针归档

这里存放**已完成使命的历史探针**：它们在写下的那一轮用于取证某个具体问题
（真机 DOM 形状、SSE 帧、CDP 附着、某次事故的复现），结论已经回写进
`doc/` 的常读文档与 `lib/` 的护栏测试，脚本本身不再被任何代码引用。

## 为什么归档而不是删除

1. **可复现性**：`doc/verify.md` 与 `doc/long-term-issues.md` 里有若干结论标注了
   「取证命令」，需要时还能按原样重跑。
2. **形态样本**：部分脚本固化了当时抓到的**真实网页形状**（如 `real-probe-*` 系列），
   是改站点适配时最省事的对照物。
3. **成本极低**：总计数十 KB，不参与 `npm test`，不影响任何构建。

## 目录约定（2026-09-16 整理）

| 位置 | 含义 |
| --- | --- |
| `test-mock/*.mjs`（顶层） | **在用**：被 `package.json` 脚本或其它代码引用，或属稳定入口（如 `real-verify.mjs`、`parse-session-log.mjs`） |
| `test-mock/archive/` | **归档**：一次性探针，无代码引用 |
| `../test/*.test.mjs` | 真正的回归护栏，`npm test` 会跑 |

**判据**（下次再要整理时照这条判，不要凭「看起来旧」）：
留 = 被代码引用或属稳定入口；归档 = 只被文档提及、且那一轮的结论已回写。

## 归档时的注意（路径变了）

归档文件的**相对导入路径已失效**（原先 `../lib/x.js`，现在需要 `../../lib/x.js`）。
若要重跑某个归档脚本，先改它的 import 前缀，或直接按脚本里的注释重建等价命令。
