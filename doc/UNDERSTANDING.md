### C7 · 中央区「三列并行对比」是新需求

| 项 | 内容 |
| --- | --- |
| 用户原话 | 「？不能说是居中的那里吗？就是现在回复 dsh 居中会话地方，然后并列显示，3 列吧，就是别人那里的多对话对比最好功能」「都要，可以自己选吧，做不到吗？不同账号就是不同来源啊」「这个啊，效率啊」「现在只有一个会话不是吗？我想要能够并排直观观看对比」 |
| 我的理解 | 在 **DSH 中央区**（现在显示对话的那块地方）做**三列并排**，每列可**自选来源**（站点 + 账号槽任意组合，可同站点多账号、也可不同站点）。目的是：**同一个问题同时问多个来源，并排看答案、判断哪个质量好**。用户强调要点是**效率**——是**真并行**，不是排队等。 |
| 核实 | ①官方有槽位 `conversation.view`（`dsh-client-ui-conversation` 的 `slots.d.ts:157`），注释写明 **rendered one at a time**——即中央区是「多个 view 标签页切换」，**没有并排分栏**，所以三列要在**自己的 view 内部**排。②`dsh-client-ui-layout` 只提供 `sidebar / main / rightbar` 三列，`main` 是 keyed、`conversation` 键保留给官方对话。③**并发是硬约束**：`relay.js` 只有**一个全局 `busy`**（L63/121/231），驱动层每个「站点×账号」实例只有**一个 `page`**（`browser-driver.js:387`）——一个页面只有一个输入框，两轮并发写同一个框必然互踩。 |
| 结论 | 走官方 `conversation.view`（合规、不注入 DOM），但**必须先解决并行底座**：每个并行来源各自一个页面。这是本轮最大的一块结构改造。 |

## 3. 验收判据（用户给定，可直接执行）

### 3.1 长跑（用户原话）

> 「至少 30 分支，调用 50 轮工具不出错」

**判据（我按此定，逐条可核对）**：

| # | 判据 | 取法 |
| --- | --- | --- |
| 1 | 单次连续运行 **≥ 30 分钟** | 会话日志首末事件时间差 `session.v3.jsonl.zstd`；或 `GET /__webcode/status` 的 `startedAt` 对照 |
| 2 | **≥ 50 轮工具调用**全部成功 | `tool/result` 事件里 `isError` 为 0；本轮 `tool/call` 计数 ≥ 50 |
| 3 | 全程**同一网页会话** | `driver.navTrace` 每轮 `requestedFresh===false`；`GET /__webcode/session-slot` 不变 |
| 4 | **无协议原文泄漏** | 助手消息正文里搜不到协议标记字符（`｜｜DSML｜｜` 等） |
| 5 | 无 `WEB_NO_PROGRESS` / `WEB_SESSION_LOST` 类报错 | `/__webcode/status` 的 `lastError` 与 `sessionCursorInvalidations` 为空/0 |
| 6 | 任务是真任务 | 用「审查本项目代码质量并出报告」这类**真实任务**，不是构造的 echo 任务（依据：用户原话「自己完成复杂任务如：审查项目代码质量/安全」） |

## 5. 我核实到的技术约束（写下来，避免后面重复踩）

1. **中央区没有并排分栏**：`conversation.view` 是「一次只渲染一个 view」，三列必须在自己的 view 内部排。
2. **并行是真结构改造**：`relay` 单 `busy` + 驱动单 `page`。要真并行，必须让每个并行来源各有一个页面（同一 Edge 多开 page，或各自浏览器实例）。
3. **附件确认判据在 DeepSeek 上不可靠**（见 C4）。长跑前若不动它，可临时把 `attachInlineLimitChars` 设 `0` 回到纯文本，避免 40 万字符灌输入框。
4. **装机 ≠ 生效**：`pnpm pack` → 装 profile → **重启 DSH** 才加载。项目已经因为「装了没重启」返工过至少两次。
5. **提交欠账是风险**：截至本轮 `git status` 有 **66 项未提交**，`origin/main` 仍停在 `6b836d2`（0.15.12）。工作树一旦出事，五轮修复与全部真机夹具同时消失。
6. **本机环境约束**：`node --test <glob>` 会 `spawn EPERM`，必须**逐文件**跑；`--test-force-exit` 在 Windows + Node 24 上有已知噪声，用它的文件请不加该开关。
7. **风控纪律**：探针间隔 ≥20s、单站点 ≤3 次/轮，命中风控页立即停。

## 6. 我理解到「不要做」的事

- 不动 DeepSeek 的**主对话**（用户多次强调「不要搞崩这个对话」）。
- 不重造官方 AgentTeams 的词汇与判据（`blockedBy` / `ready` / `writeScopes` 沿用官方）。
- **不伪造「已派发」**：拿不到执行能力时必须抛可识别错误，不许假装成功。
- 不把「装了没重启」当成已修好。
- 不在没有读数的情况下宣称某条已修（区分「取证」与「推断」是项目既有纪律）。
