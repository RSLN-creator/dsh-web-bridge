## 三、九个阶段（分界取「代码与纪律的转折点」，不按日历等分）

编号 ①–⑨ 与 [`progress.md`](progress.md) 顶部自动索引的时代分组**一致**。

### ① 立骨架（2026-09-07 ～ 09-09，0.5–0.6.x）

- 首提交是 0.5.1 工作树快照；随后 0.6.0 打包并装进 DSH web profile。
- 打通的是**最小闭环**：DeepSeek 网页「深度思考」pill 同步、思维链透传、多站点 UI 起步、
  工具错误恢复（裸 fence 调用解析）。
- 这一阶段还没有「协议真源」这个概念，工具调用形状是分散解析的。

### ② 纪律成型（0.09-10 ～ 09-21，0.14–0.16.x 前段）

> **这是本项目性格形成的一段**：从「能跑」转向「结论必须可复现」。

- 提示词工程立场、注释风格、评审指南、真实验收矩阵陆续成文（`doc/` 的常读文档多半来自这一段）。
- `doc/user-voice-log.md` 建立：**用户原话成为判断意图的第一手依据**。
- 闸门体系（`lint-comments` / `check-ledger` / `check-repo-hygiene`）转正。
- 三次「工具协议漂移」事故之后，`lib/agent-preset.js` 被确立为**协议唯一定义处**（三条红线之一）。

### ③ 契约与解码器收口（0.09-18 ～ 09-21，0.16.x）

- `SITES` / `contract.js` / `decoder.js` 三家分工定型；解码器改成**族内继承 + 按站点子类**。
- 0.16.x 是**版本号最密**的一段（`CHANGELOG` 里 0.16.x 占 27 个进度小节）。
- 关键教训在这一段入账：`finish()` 的「失败分支丢弃已解内容」一次修了 4 个解码器族——
  这是后来「站点差异外移」不做「按站点复制」的核心论据之一。

### ④ 镜像 / 画面流路线（0.09-23 ～ 09-25，0.17–0.21.x，**部分已回退**）

- 为「右栏看得见真站点」试过两条路：**同源镜像** 与 **WebRTC 画面流**（0.20.x–0.21.x）。
- **0.19.13 按用户指令完全回退**了换路线的版本（`ac449f2`，信息逐字为
  「按用户指令完全回退换路线版本（0.20.0–0.21.2）」），镜像恢复为默认。
- ⚠ 因此 **0.20 / 0.21 的版本号在 `CHANGELOG` 与 git 历史里存在，但不是当前路线**。
  检索版本号时不要把它们当成「现在的版本」。

### ⑤ 0.19 早期：多账号 / 思考等级 / npm 首发（0.09-22 ～ 09-28，0.19.0–0.19.9）

- 同站多账户落地（账户槽模型），`accounts.js` 成为纯函数身份层。
- 思考等级（think effort）逐站取证；四站**刻意不声明**的决策也在这一段。
- **npm 首发**：`0.19.26`，发布于 2026-09-26T12:57Z（`npm view dsh-webcode-bridge time`）。

## 五、这份文档怎么维护

- **只写已经发生的事**，每条读数写**取法**；写「实测」的必须有命令。
- 阶段分界变了（出现新的转折点）才加/改阶段；**普通版本推进不改本文件**——
  那属于 [`progress.md`](progress.md) 与 `CHANGELOG.md`。
- 本文件与 [`progress.md`](progress.md) 顶部的**自动索引**共用同一套时代编号（①–⑨）：
  改了一边要同步另一边（索引由 `scripts/gen-progress-index.mjs` 生成，时代定义在那个脚本里）。
- 用户说出新的意图或推翻旧意图 → 改 [`PROJECT-INTENT.md`](PROJECT-INTENT.md)，不是本文件。
