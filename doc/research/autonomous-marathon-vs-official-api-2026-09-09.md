# 自主马拉松轨迹对比：Web Bridge 0.6.9 vs 官方 API（2026-09-09）

## 测试设计变更

按 2026-09-09 用户要求，真机测试从「单功能契约自检」（real-verify）升级为：

1. **无外部输入的自主长时间运行**：只下发一个任务（深度代码安全审查），
   之后模型全权决策读什么、grep 什么、跑什么命令、何时收束；期间零人工干预、
   零外部提示。工具错误真实产生并回显，验证自主恢复而非编排好的脚本。
2. **轨迹留档**：每轮任务文本、思维链分片、工具调用、真实结果、轮次耗时全部
   落盘 JSONL（`package/dsh-webcode-bridge/test-mock/trace-probe17-*.jsonl`，
   与 DSH 会话存档同形状，可直接被后续对比脚本消费）。
3. **与几周前官方 API 轨迹对比**：基线取 DSH 会话存档中 provider=
   `deepseek-official` 的真实历史会话（2026-08-14 ~ 08-24，约 2-4 周前，

## 首跑暴露并修复的三个真实缺陷

1. **裸 `<invoke>` XML 调用被静默丢弃**（lib/agent-preset.js）：
   模型在多轮工具回读后直接输出 DSH 原生 XML 调用语法（无 fence、无 mcp_action），
   旧解析器四种形状全不认 → 第 3 轮裸奔。已加 invokeRe 归一（parameter 全收、
   散文举例不触发），probe-17 终跑 14 轮中大量调用正是该形状——若未修复，任务
   在第 1 轮后即断。回归测试 3 例新增。
2. **DSML 协议标记噪声**：网页流式偶发把标记输出成 `<｜｜DSML｜｜tool_calls>`
   （全角竖线 U+FF5C 成对出现、丢开头 `<`），导致调用不可解析且伪标记漏进正文。
   与 reference/deepseek-free-api 的 strip_dsml_markup 同源问题，已按其思路归一化
   （三种变形全收、散文提及 DSML 不触发），回归测试 4 例新增。
3. **探针 shell 执行器 maxBuffer=1MB 过小**（test-mock 自身问题，非桥缺陷）：
   `Get-ChildItem -Recurse` 全仓清单类命令超限抛 ENOBUFS 被计成工具错误，
   首跑 errRate 虚高到 16.1%。已放大到 16MB（与 DSH 宿主 pwsh 同量级），
   终跑 errRate 降到 9.7%，剩余 3 错全部是模型 Unix/Windows 命令习惯冲突
   （`ls -la`、`&&` 链）且同轮自愈。

## 对比结论

- **能力面上已对齐**：多轮自主探索、错误自愈、思维链贯穿、多工具组合在 web 桥上
  全部成立，无裸奔、无卡死、无静默丢调用。
- **差距点（如实记录）**：
  - 自然收束未达成——14 轮上限被截停时模型仍在扩大核查范围（审计倾向过强），
    官方 API 会话在用户轮驱动下能收束。属任务设计/提示词问题，不是桥的协议缺陷；
  - errRate 9.7% 高于官方 0-3.8%：根源一半在探针执行器环境（已修 1MB 问题），
    一半在模型跨 shell 习惯（`ls` vs `Get-ChildItem`），桥的回填链路均正确工作；
  - 思维链 10k 字远小于官方大会话的 174k-378k：官方基线是多用户轮长会话的累计值，
    单任务口径下 0.6.9 的 8k-10k 与官方单轮密度（fda598ba 35 调用 5k 字）同量级。
- **协议健壮性净增**：本轮把调用形状容错从 4 种扩到 7 种
  （tag fence / mcp_action fence / 裸 JSON fence / Calling+JSON / 裸 invoke XML /
  全角 DSML / 丢头 DSML），全部配回归测试（40/40 绿）。
