## 一、设计空间：四个候选，只有两个站得住

| # | 方案 | 是否真的隔离 | 本插件能否做到 | 判断 |
| --- | --- | --- | --- | --- |
| A | 只留提示词约定（**现状**） | ❌ 不隔离 | ✅ 已做 | 保留，但必须**改掉那句做不到的指令** |
| B | **桥侧产物围栏**（只允许写本列目录） | ✅ 对插件自己的写入口是真的 | ✅ 能 | **采用** |
| C | **让产出目录真的存在**（插件落盘） | ✅ 使 A 的约定变成实物 | ✅ 能 | **采用** |
| D | 每列独立 DSH 会话（各自 cwd） | ✅ 真正的 OS 级隔离 | ❌ 跨层改造 | **不做**，只如实记录 |

### 1.1 为什么 D 出局（要写清楚，否则下一轮会有人再提一次）

D 是唯一能做到「真正的文件系统隔离」的路，但它有两个独立的问题：

1. **它要改产品**：每列一个独立 DSH 会话 ⇒ 三列不再是同一个对话区里的并列视图，
   而是三个会话。用户要的是「中心对话区并列不同模型」（`user-voice-log` 2026-09-22
   原话），D 把这件事换成了别的东西。
2. **它要跨层改造**：据第一轮取证，列身份要沿
   `provider → adapter → 工具调用元数据` 全链带下去，才能在
   `sandboxPolicy.resolve()`（官方只认 `session`）那一层生效。
   这不是本插件单方面能完成的，也超出用户「不要动别的模型实现根基」的约束。

**它唯一正确的归宿**是文档：让下一个读到这里的人知道「真隔离长什么样、代价是什么」，
而不是误以为我们做的 B/C 是 OS 级隔离。

## 二、采用的设计（B + C + 诚实披露）

### 2.1 B：桥侧产物围栏

**范围必须说死**：围栏只保护**本插件自己的写入口**。它不拦模型，因为这条路径上
没有模型写入（第一轮 §二）。

判据**照抄官方 `dsh-fs-sandbox` 的 containment 口径**，逐条对应：

| 官方做法 | 本插件对应 |
| --- | --- |
| 先 canonicalize，再判包含 | 目标路径 `realpath`（含最深已存在祖先）后判包含 |
| 包含判据要认文件系统身份（Windows 8.3 / 大小写） | 用同一个 `isPathUnder` 思路，lexical 快速路径 + 身份回退 |
| 委托前**再** canonicalize（缩 TOCTOU 窗口） | 返回「刚刚重新解析过的那个 target」去写，而不是先验后写原路径 |
| 拒绝时抛结构化错误 | 抛带 `code` 的错误（如 `COLUMN_FS_DENIED`），UI 可显示 |
| containment ≠ kernel boundary，如实标注 | 注释与文档写同一句，不吹成「沙箱隔离」 |

允许的根：`<workspace>/.hwb/cols/<scope>-<key>/`（`scope` 与 `key` 都已过
`safePathSegment` 白名单，见 `column-context.js:50`）。

**为什么根要用 `scope`+`key`**：0.19.23 修过一个真缺陷 —— 只用 `c1/c2/c3` 时，
两个不同 DSH 会话的第 2 列会写同一个 `.hwb/cols/c2/`，草稿互相覆盖
（`column-context.js:79-87`）。围栏的根必须与那条修复同源。

### 2.2 C：让产出目录真的存在

这是**修第一轮 §四那个谎**的唯一干净办法：既然提示词说「产出写这里」，
那就让插件**真的把这一列的产出写到那里**。落地形态（实施轮定稿，候选）：

- 每列一轮完成后，把该列回复文本落成 `<根>/<轮次>-reply.md`；
- 若回复里有**围栏代码块**，额外落成 `<根>/<轮次>-<语言>.<扩展名>`
  （这是「方案探索」最有用的一步：内容变成可打开、可 diff 的文件）；
- 落盘是**纯增量**的：不碰主工作树，不碰任何别列的目录。

这样「探索列的产出在 `.hwb/cols/<scope>-<key>/`」从一句约定变成**用户看得见的事实**，
主审列的统一审查也终于有实物可吃（而不是只有引用通道里的文本）。

### 2.3 诚实披露（三处，都要写明「这不是隔离」）

1. **提示词**：把「不要直接修改主工作树」保留为**约定**，但**删掉**
   任何暗示模型自己会写文件的措辞 —— 改成「本列没有文件工具」这个事实。
2. **文档**：`column-context.js` 文件头 + 本两轮文档，统一口径
   「围栏只覆盖桥自己的写入口；模型侧无写入通道」。
3. **UI**（可选，实施轮决定）：列的极小徽标处 hover 提示一句
   「三列共享一个工作区；本列的产出落在 `.hwb/cols/…`」。

## 三、边界诚实：这一版**不**声称什么

按本仓库纪律，把话说死比说漂亮重要：

| 不声称 | 理由 |
| --- | --- |
| ❌「三列已被文件系统隔离」 | 它们本来就没有写入通道；且 DSH 侧共享一个 `cwd` |
| ❌「模型无法越界写」 | 模型侧根本没有写的能力，谈不上「无法越界」 |
| ❌「这是安全边界」 | containment，不是 kernel boundary（官方同一口径） |
| ❌「主工作树受到保护」 | 保护只覆盖插件自己的写入口，不覆盖 Harness 的工具执行 |
| ✅「本列产出只落在本列目录」 | 这是围栏**真实**覆盖的范围 |
| ✅「三列互不覆盖对方的草稿」 | 命名空间 + 围栏共同保证，**可测** |

## 四、验证计划（实施轮照此执行）

判据必须**成对**（本仓库反复记过的教训：只测一侧的判据能过掉反向实现）。

### 4.1 围栏单测（新文件，纯函数、离线可跑）

| # | 用例 | 期望 |
| --- | --- | --- |
| ① | 根内正常路径 | 允许 |
| ② | 根本身 | 允许 |
| ③ | `../` 逃逸 | 拒绝 |
| ④ | 多级 `../../..` | 拒绝 |
| ⑤ | 绝对路径（`C:\Windows\…` / `/etc/…`） | 拒绝 |
| ⑥ | 前缀伪装（`…/cols/c1-evil/x`） | 拒绝（不能只做字符串前缀） |
| ⑦ | 大小写别名 | 拒绝（Windows 身份回退） |
| ⑧ | 8.3 短名（`PROGRA~1`） | 拒绝 |
| ⑨ | 分隔符混用（`\` 与 `/`） | 归一后判定，不接受混写绕过 |
| ⑩ | 全角/百分号编码形态 | 由 `safePathSegment` 在**拼根之前**拦掉 |

③-⑩ 每一条都要**红得起来**：把围栏换成 `return target`（直接放行）⇒ 全部变红。

### 4.2 产出落盘的行为测

| # | 用例 | 期望 |
| --- | --- | --- |
| ⑪ | 一列一轮完成 | 该列目录下真的出现文件（**不是**只断言调用了函数） |
| ⑫ | 两个不同 `scope` 的第 2 列 | 落进**不同**目录（0.19.23 那个缺陷的回归钉） |
| ⑬ | 越界写请求 | 抛错且**磁盘上没有**该文件（成对：拒绝 + 无副作用） |

### 4.3 文案测（防撒谎）

| # | 用例 | 期望 |
| --- | --- | --- |
| ⑭ | `columnGuidance` 输出 | **不得**再出现「你的产出请写入」这类要求模型自己写文件的措辞 |
| ⑮ | 同一输出 | 仍必须写明「这是工作区约定，不是强制隔离」 |

### 4.4 现有闸门

`team-compare` / `client-render` / `hooks-order` / `column-context` 全绿，
`lint-comments` 与 `check-ledger` 全绿。真机浏览器探针在本机沙箱
`spawn EPERM`（第一轮已验证是环境限制，非代码问题），实施轮不依赖它。

## 五、实施轮的工作清单（明确不做的事也列出来）

**要做**：

1. `lib/column-digest.js`（或并入 `column-context.js`）：`columnRoot()` +
   `assertUnderColumnRoot()`（canonicalize-then-contain，含身份回退）；
2. `web-control.js` 的 `POST chat`：列回复落盘走围栏（**只加落盘，不改发送语义**）；
3. `column-context.js`：改掉第一轮 §四那句做不到的措辞（C 落地后改为事实陈述）；
4. 新增 `test/column-sandbox.test.mjs`（4.1-4.3 的判据）；
5. 文档：`column-context.js` 文件头 + 本两轮文档口径统一。

**不做**（越界就是违约）：

- ❌ 不改真实桥接 web 端的行为（不改 `browser-driver.js` 的抓帧/发送、
  不改任何站点的选择器或协议适配）—— 用户明确要求；
- ❌ 不做 D（每列独立 DSH 会话）；
- ❌ 不声称这是安全边界或 OS 级隔离；
- ❌ 不动 `sandboxPolicy` / `dsh-fs-sandbox` 等官方包。

## 六、第二轮的一句话结论

> 沙箱的**正确形状**是：**围栏（B）只护住插件自己唯一的写入口，落盘（C）让
> 「产出目录」从一句谎话变成实物，披露把「三列共享一个工作区」如实说出来。**
> 真正的 OS 级隔离（D）写进文档、不做 —— 因为它要改产品、且要跨层改造。
