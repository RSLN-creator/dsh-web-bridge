# 设置界面文案总表（0.16.38 学术精简）

> 界面上的每一句提示都压到一句可操作的话；**被删掉的完整解释全部记在这里**，
> 保证信息不丢、只是不再占用界面。改文案时同步改本文件。

## 0. 为什么要有这份文件

用户 0.16.38 原话：「请你简短和规范设置所有内容的表述和大意，保持严谨和大意不变，做到学术
精简！具体解释你可以全局本地写文档好好说明！而不是在设置界面那么啰嗦繁琐」。

因此界面文字只有一条判据：**读者能不能据此做一个决定**（选哪个、点哪里、失败会怎样）。
「为什么这么设计」「历史事故现场」「回落链的第几档」属于文档，不属于设置面板。

## 1. 作用域：哪张卡属于哪一页

用户原话：「将全局界面设置『账户与登录管理』『首轮提示词』入口删除……然后模型每个网站例如
『deepseek』标签页 —— 请你将『正在运行（子代理 / Team）』『模型管理』『提示词投递』
『会话与子代理』一样界面表面删除 —— 两者逻辑上单独适配全局和单独站点！你却全都有放置」。

| 卡片 | 全局页 | 站点页 | 为什么 |
| --- | --- | --- | --- |
| 账户与登录 | — | 有 | 账户是**站点**的属性（每站一套登录态，甚至每站多槽） |
| 该站点的模型（本网站默认 / 主线落点 / 深度思考） | — | 有 | 「这个网站用哪一支」是站点问题 |
| 该站点的首轮提示词（文件 + 本网站指令 + 只读模板） | — | 有 | 用户要求「每个单独模型都只能改自己的」 |
| 该站点的排队间隔 | — | 有 | 限流窗口按站点计 |
| 发送间隔（全局） | 有 | — | 它是**回落档**：站点没覆盖时用它 |
| 提示词投递 | 有 | — | 进程级选择，站点差异走驱动自己的站点禁令 |
| 连接（中继 + 授权 + 主线落点） | 有 | — | 授权是进程级；主线落点只读，点它跳到对应站点页 |
| 速度与等待 | 有 | — | 全局实测指标 |
| 会话与子代理 | 有 | — | 子代理策略是会话级 |
| 正在运行（子代理 / Team） | 有 | — | 进程级事实 |
| 全局指令 | 有 | — | 注入每个新网页会话的公共段 |
| 首轮提示词（只读总览，每站一行 + 文件路径） | 有 | — | 横向核对十个站点，不在这里编辑 |

**模型配置为什么只留站点页**：全局的「默认模型」其实是「主线落点（站点 + 模型）」，它已在
全局页「连接」卡里以只读一行 + 跳转按钮的形式存在；再放一份可编辑的「模型管理」等于同一件事
有两个入口，而用户要的正是把这两层分开。

**两处必须成对**：`GlobalPrompt` 只允许挂一次。0.16.38 拆分卡片时曾同时被「全局指令」卡与
`PromptSection` 渲染，同一设置出现两个输入框——改一个另一个不知道，保存后互相覆盖。护栏
（client-render 的作用域用例）现在钉住「哪张卡在哪一页」。

## 2. 逐条对照（界面文案 → 完整解释）

### 2.1 全局指令

- 界面：`追加一段 [全局指令] 注入每个新网页会话的首条消息。`
- 完整解释：全局指令拼在首轮正文的 `[系统指令]` 之后、工具教学之前（`agent-preset.js`
  的 `buildPreset`）。它进**契约指纹**，所以改了它下一轮会整段重建一次网页会话
  （不是缺陷：旧首轮里那一句撤不回来）。
- 上限 4000 字符（前后端同一条上限）。

### 2.2 本网站指令

- 界面：`本网站指令：只对本站点生效，注入该站点新网页会话的首条消息。`
- 完整解释：落在 `extraPromptBySite[siteId]`，与全局指令同轮注入、全局在前，标注为
  `[本网站指令]（<siteId>）`。它同时进**契约指纹**与**内容指纹**——两处都进是必须的：
  只进契约指纹时，「契约没变 + 尾部没变」会让这一轮什么也不发；只进内容指纹则会每轮
  判 `anchor-lost`。
- 空串 = 删键（回落成「没有这一段」），不是「注入一个空段」——后者会白白整段重建一轮。

### 2.3 提示词文件

- 界面：一行等宽路径 + `用默认程序打开`。
- 完整解释：路径由**服务端**用 `lib/prompt-store.js` 的 `sitePromptPath(dir, siteId)` 现算
  （默认 `~/.dsh/webcode/prompts/<siteId>.md`）。请求体只带 `siteId`，路径不接受调用方传入
  ——于是这条路由的能力被钉死在 `prompts/` 下那几个 `.md`，拿不到任意文件读写的把手。
- 文件在**首次整段重建**（fresh 首轮）时写入，逐轮覆盖；没发过消息就没有这个文件，此时
  如实回 `PROMPT_FILE_MISSING` 并把路径显示出来，不静默失败。
- 打开方式：Windows `explorer.exe <file>`，失败回落 `rundll32.exe url.dll,FileProtocolHandler`；
  macOS `open`；Linux `xdg-open`。**argv 调用、不经 shell**（用户目录名可能含空格或引号）。
- 相关环境变量：`WEBCODE_PROMPT_STORE_DIR`（`off` = 显式关闭落盘）。

### 2.4 只读模板

- 界面：`查看该站点此刻的只读模板`（默认折叠）。
- 完整解释：模板由桥按**本会话工具清单**现算（`serializeFirstTurn`），因此它不是一个可以
  编辑的固定字符串。设置页显示的与真正发出去的是同一个函数的输出——两处各拼一份协议必然
  漂移，这正是 `prompt-variants.js` 头注写下的纪律。
- 「实际使用：<协议名>」是该站点真实走的那一支（deepseek 官方模板 / glm 代码块 / 其余标签形状）。

### 2.5 发送间隔（全局）与站点间隔

- 界面：预设下拉 + 毫秒输入 + 基准下拉 + `被限流时按 max(间隔, 10 秒) 自动退避重试，最多 2 次。
  站点级覆盖见该站点的 tab。`
- 完整解释（原文照录，界面不再显示）：「两次向同一网站**发送**之间的最小间隔。两个基准防的是
  两件不同的事：**距上次发出**（默认）防站点的『消息发送过于频繁』滑窗限流，它按请求到达计、
  与生成耗时无关，所以上一轮跑得久时本轮无需再等；**距上次回复完成**防对话节奏贴得太紧
  （『它刚答完我立刻回』），此时上一轮跑了多久不影响本轮，答完那一刻起重新数满。实际等待、
  目标值、基准与『距上次发送』都在输入框底下那枚药丸的点击面板里逐项显示；该设置会落盘，
  **重启后第一轮同样生效**。」
- 回落链：站点覆盖（`sendGapMsBySlot`）→ 全局（`sendGapMs`）→ 0。见 `accounts.sendGapForSlot`。

### 2.6 提示词投递

- 界面：`「附件投递」把超过阈值的正文改为附件上传，绕开网页输入框的写入卡死与截断；任何一步
  失败都会自动回落纯文本。`
- 完整解释：阈值 `attachInlineLimitChars` 默认 60,000 字符，依据是 0.16.3 真机事故
  （127,888 字符纯文本灌进输入框，整轮 112 秒零事件被看门狗判死）。**该站点是否走附件由驱动
  决定**（DeepSeek 有站点禁令：网页收得下但读不到内容），因此界面上的「当前生效」读数是按
  **实际站点**算的，不是把全局开关复述一遍。
- 探针：向当前网页会话上传一个 `webcode-probe.md`，**只上传、绝不发送**，上传后立即尝试清理
  并如实报回证据节点、命中数与清理结果——这是「附件到底行不行」唯一不消耗真实会话的读数。

### 2.7 连接

- 界面：`首次使用请授权一次；关闭后所有网页调用都会被拒绝。`
- 完整解释：授权（consent）是进程级；能写配置目录时永久保存（`requireConsent` 由
  `cordis.patch.yml` 打开）。关闭后所有网页调用被拒。
- 「主线落点」只读行显示 `defaultModel`（全局单值）与它的模型名；站点级模型覆盖在站点页。

### 2.8 会话与子代理

- 界面：`独立（推荐）：每个子代理自己的新网页对话` / `共用：所有子代理与主会话共用一个网页
  对话`；`跟随主线站点（默认）`；`N 个网页会话槽；子代理按 agentId 分到同账号新对话，与主线
  上下文互不污染。`
- 完整解释（原文照录）：「子代理网页会话与主线**相互隔离**：各自独立的网页对话，上下文互不
  可见。『跟随主线』时子代理开在主线站点——同一站点两路消息频率叠加，容易触发站点限流
  （『消息发送过于频繁』）；给子代理选另一个站点即可分流。子代理站点的登录复用与主站完全
  相同的一套登录逻辑，登录态按站点各自持久化：与主线同站点时两者天然共享登录，跨站点互不
  影响。」「主线→子代理 / 子代理→主线」两颗按钮**只单向同步站点选择**，不迁移登录态。

### 2.9 正在运行 / 速度与等待

- 界面：花名册状态词（工作中 / 空闲 / 启动中 / 未加载（可唤醒）/ 已结束）+ 速度条。
- 完整解释：颜色**不得是唯一载体**——状态词与色点必须同时出现（调研 §1）。`inactive` 的
  官方语义是「成员存在但未加载，唤醒时仍会收到排队消息」，不是「已停止」。「读不到花名册：
  <原因>」与「确实没有成员」必须分开说：前者是故障，后者是状态。
- 累计等待时长不在这里重复显示：它与输入框底下那枚药丸读**同一份账本**，重复渲染会被读成
  两个不同的数（0.15.10 已按用户要求删掉那一块）。

### 2.10 右栏与站点 tab（不在设置页，但同属本轮）

- 站点 tab 条**横排单行 + 滚轮横向滚动 + 不显示滚动条**：`flex-wrap:nowrap` +
  `overflow-x:auto` + `scrollbar-width:none` 与 `::-webkit-scrollbar{display:none}`；滚轮用
  **非 passive** 原生监听映射到 `scrollLeft`（React 的 `onWheel` 在根容器上是 passive，
  `preventDefault` 会失效/告警）。
- 等待药丸**逐项等于官方**：字号与行高挂在 wrap（与官方 `StatsPills` 的 root 同形），
  pill 只声明 `padding:1px 8px` 与 `gap:6px`，**不声明 height**（官方靠 line-height +
  padding 定高）。此前多出来的 `height:calc(28px + …)` 与 24px 行高基，正是同一行里两枚
  药丸**不等高**的原因——用户说的「没适配」在数值层面就是它。
- 等待 wrap 必须**可收缩**（`flex:0 1 auto`）：旧值 `flex:none` 禁止收缩，窄栏下官方药丸
  在缩、这一枚不动。
- 站点选择框（首屏网格）与站点目录：宽度上限交给内层卡片（`width:min(100%,440px)` 且
  `margin:0 auto`），外层容器满宽 + `padding-inline:clamp(...)`，于是「不超 440px」与
  「两侧留空隙」同时成立。
- DeepSeek 鲸鱼图标：路径坐标是 23.16×17.04 的原始视箱，**必须等比缩放**再居中
  （旧实现只 translate、没有 scale，右边因此越出图标框）。
