# 真机复核二手逆向结论

## 输入
- 基于二手调研（GitHub/博客）得出的网页逆向结论，尤其涉及请求字段取值（如 model_type）、DOM 选择器、SSE 帧格式。

## 执行
1. 找到已登录的真实浏览器 profile（`Default/Local Storage/leveldb` 里搜 `userToken`）。
2. 用 playwright-core + 系统 Edge 启动该 profile，逐 profile 打开目标站点，dump `location.pathname`（是否 `/sign_in`）+ textarea 数量区分「token 失效」vs「选择器变更」。
3. 直接发一轮真实请求，读取页面 `diagnostics()` 捕获的 `requestMetadata`，对照二手结论逐项验证。
4. model_type 等取值必须以真机请求为准：dev 环境抓到的值 > 二手文档 > 猜测。

## 环境依赖
- playwright-core、系统 Edge、已登录 profile。

## 常见陷阱
- 二手调研可能反过来把对的结论推导成错的——本项目曾据此把 `vision→'vision'` 错改成 `vision→'default'` 而让识图误报。改代码前先用真机探针确认取值。
- login profile 会失效：`.edge-real-profile2` 早期可用，改名测试后跳 `/sign_in`；`.edge-real-profile` 始终有效。
- 隔离 profile + `storageState` 注入登录态对 deepseek 不生效（依赖 cookie 而非仅 localStorage），直接用原 profile 最可靠。
