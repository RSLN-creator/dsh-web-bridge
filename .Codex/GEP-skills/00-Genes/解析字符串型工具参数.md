# 解析 DeepSeek/OpenAI 风格的字符串型工具参数（arguments）

## 输入
- 网页模型或 API 把工具参数输出为「转义 JSON 字符串」而非对象：
  `"arguments": "{\"command\":\"hostname\"}"`（OpenAI function-call 传统形态）。

## 执行
```js
const normArgs = (value) => {
  if (value && typeof value === 'object' && !Array.isArray(value)) return value;
  if (typeof value === 'string' && value.trim()) {
    const first = value.trim()[0];
    if (first === '{' || first === '[') {
      try {
        const p = JSON.parse(value);
        if (p && typeof p === 'object' && !Array.isArray(p)) return p;
      } catch { /* 保持回落 */ }
    }
  }
  return {};
};
// 然后在所有解析工具调用处用 normArgs(obj.arguments ?? obj.input ?? obj.parameters)
// 替换原先只认 object 的取值逻辑。
```
- 测试构造真实转义形态的围栏，一定要用 `JSON.stringify` 生成，切勿在源码里手写转义：
  ```js
  const fence = JSON.stringify({ mcp_action:'call', name:'pwsh', purpose:'x', arguments: JSON.stringify({ command:'hostname' }) });
  ```

## 环境依赖
- 纯 JS；无关 crates。

## 常见陷阱
- 误区 A：只写 `typeof v === 'object'` 就 `return v`，字符串参数被静默丢成 `{}` → 工具空参执行失败 → 桥接上报 empty response。
- 误区 B：在 ESM 测试源码里手写 `\\"` 转义，转义层级出错导致 JSON.parse 失败，误以为解析器有 bug；应程序化构造。
- 误区 C：解析成功的字符串也要再 `JSON.stringify` 返回给 DSH 工具块时保持一次转义即可，勿双重包裹。
