# 多站点模型路由架构（限定 id + 独立驱动 + 归一化单点）

## 输入
- 一个「网页 AI 桥」需要接入多个内容服务（DeepSeek/GLM/ChatGPT/Kimi/…），每个站点有独立登录态、DOM 契约、SSE 格式。
- 宿主侧（DSH/OpenAI 前端）用一个模型选择器暴露全部模型。

## 执行
- 模型目录收口：providers.js 里 `SITES` 数组 + `listAllModels()` 返回 `'site:model'` 限定 id + 能力元数据，DSH 选择器与 /v1/models 同源，避免两份列表漂移。
- 独立驱动容器：`driverFor(siteId)` —— 主站点（deepseek）沿用默认 driver（兼容测试注入），其余站点懒创建，profile 目录按站点分开（`profileDir/sites/<siteId>`），否则登录态/会话存储串号。
- 限定 id 全程携带：buildTurn 的 `meta = { model: siteId + ':' + model, siteId }`；executor 按 `meta.siteId` 选 driver，模型 id 再经 `qualifyModelId()` 归一化（裸 id 补前缀、已限定原样、空值透传）。
- 解码器注册表：`globalThis.WebCodeStreamDecoders` 按站点 `decoder` 字段取用；`decoder:'dom'` 的站点（无稳定网络流）走页面终态抓取兜底。
- 按站点登录/状态：login 接口带 `siteId` 参数路由到对应 driver 的 openLogin；status 聚合 `sites[]`（未初始化给占位、不启动浏览器）。

## 环境依赖
- playwright-core + 系统 Edge 持久 profile；解码器为 content-script 风格全局注册表（new Function 加载）。

## 常见陷阱
- 只注册 providers.js 但不改 `listModels` → 模型选择器还是旧的几个（本次踩坑：`WEB_MODELS = DEEPSEEK.models`）。
- 只改路由不改 meta → 裸模型 id 跨站点重名时串到错误站点；`resolveWebModel().id` 会丢掉站点信息，必须连 `siteId` 一起传。
- 所有站点共用同一 profile 目录 → 第二个站点的登录会覆盖第一个站点的 cookies。
- 每个站点独立 driver 但 dispose 只关主 driver → 泄漏浏览器进程；遍历关闭全部。
