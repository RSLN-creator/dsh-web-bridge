# 新建单测护栏暴露字段误归一

## 输入
- 一段「看似已实现、实则有隐藏丢弃路径」的解析函数（如 SSE decode 的 fragment 归一）
- 难以用真机回放定位，或想防未来回归

## 执行
1. 读解析函数，找出所有「分支丢弃」点（如 `content: type === 'X' ? c : ''`——非 X 类型会被清空）。
2. 对照文件头注释声明的数据形状（如「fragments 存 THINK/RESPONSE」），找出与实现不自洽处。
3. 写单测：构造含两种形态的输入（fragments 数组 + 独立 op），断言「被丢弃路径」是否真的向回调暴露：
   `assert.ok(collector.join('').includes('期望文本'), '该片段应经回调暴露')`
4. 若测试 FAIL 且出现 `expected true, got false`——多半命中了真实 bug（路径被清空/短路），而非测试写错；去修源逻辑。

## 环境依赖
- Node ≥18（node:test + assert/strict）。

## 常见陷阱
- 先确认输入形态与真实生产一致（是否为 fragments 数组的 THINK，还是独立 reasoning_* op）；两种形态都要覆盖。
- 别把「测试流没结束（缺 SET status=FINISHED）」误判成产品 bug——先看的是断言是 `complete` 还是 `content` 相关。
