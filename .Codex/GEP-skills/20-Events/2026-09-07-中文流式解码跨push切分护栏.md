# 事件：为中文流式解码加固跨 push 切分护栏

## 背景
- 方向：更深的源码鲁棒性（不依赖外部环境）。核心问题：真实流式下 capture 增量 slice 会分多次 push，SSE data 帧可能在任意位置（含汉字旁）被切开，需确认 decoder 不丢字/不乱码/不裂帧。

## 执行过程

[2026-09-07] 核对 decoder 设计
- 技术: lib/decoder.js 的 SseDecoder.push 用 this.buf 累积、按 \n\n 分帧（跨调用缓冲完整行）；capture 层（browser-driver init 脚本）已是解码后的字符流（fetch 用 TextDecoder stream:true、XHR 用 textContent slice），无 UTF-8 字节级截断。判定：跨 push 切分在字符层面本就鲁棒。
- 操作: 只读核查 decoder.js + browser-driver.js capture 段。

[2026-09-07] 加硬断言护栏
- 技术: 在 regression.test.mjs 新增用例：把一条含 ready(带前缀 content) + APPEND content + SET status=FINISHED + close 的完整 SSE 流，按固定 2 字符步长切成极多片段逐段 push，断言 finish() 完整无乱码（complete:true，文本 '安全排查完成，未发现硬编码凭据。'）。
- 操作: 首次构造漏了 SET status=FINISHED 帧→decoder 正确返回 incomplete（非 bug 而是流未完成）；补齐后 pass。
- 功能: 中文流式解码得到了跨任意切分的回归护栏，防未来改动破坏。
