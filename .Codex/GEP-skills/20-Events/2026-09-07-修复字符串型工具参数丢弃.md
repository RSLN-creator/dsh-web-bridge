# 事件：修复 DeepSeek 网页"字符串型工具参数被丢弃"致 empty response

## 背景
- 用户上传真实使用轨迹：网页模型把工具参数 `arguments` 输出为「转义 JSON 字符串」（如 `"{\"command\":\"主机命令\"}"`，同 OpenAI 风格），桥接解析后参数变空或格式错，导致工具执行失败 → 上报 "empty response from web AI"、"没有正确格式？没有正确响应"。
- `/goal` 要求"每个工具的实际调用都要测试"，且用户强调代码改动后需从工程角度补全到真正达标。

## 执行过程

[2026-09-07] 定位根因（agent-preset.js / parseAgentReply）
- 技术: 真实轨迹里 DSH 工具块 arguments 是转义字符串；parseAgentReply 的 `takeObj` 只认 `typeof obj.arguments === 'object'`，字符串型参数被回落到 `{}`；`**Calling:**` 分支也只认 object，字符串会被整体丢弃。
- 操作: 通读 agent-preset.js parseAgentReply 段，与 OpenAI 参数输出惯例对照。
- 功能: 确认这是"工具拿到空参数 → 执行失败 → 桥接空响应"的根因，而非网页本身问题。

[2026-09-07] 实现归一化修复
- 技术: 新增 `normArgs(value)`：object 直达，JSON 字符串（以 `{`/`[` 开头）解析一次成 object，失败安全回落 `{}`；在 mcp_action 围栏、`**Calling:**`、legacy `{"tool":...}` 三处统一调用；并把 `**Calling:**` 的 body 兼容"整体是转义字符串"或"含 arguments 字段"两种情况。
- 操作: lib/agent-preset.js（parseAgentReply 重写）。
- 功能: 字符串型参数被正确还原为对象，adapter 的 `JSON.stringify` 产出规范 `{"command":"..."}`，DSH 工具真正拿到参数。

[2026-09-07] 回归与端到端验证
- 技术: parse.test 新增强转义字符串参数 4 例（构造时用 JSON.stringify 保证真实转义）；m4 长自用安全案例首条 read 围栏改为字符串型参数。
- 操作: test/parse.test.mjs、test-mock/run-m4-security-review.js。
- 功能: parse 12/12、m1、m4（字符串参数端到端）、regression 8、mirror 全 PASS。

## 结论
- ✅ 字符串型 arguments 全路径（解析→DSH 工具块→本地执行）被修复并有测试覆盖。
