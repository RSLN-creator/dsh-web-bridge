## 背景

0.9.7 收尾后做「长期真实调用」复跑，用户反馈相比 0.9.3 左右「回复直接减少/缺失/
没法同一对话继续」。定位：0.9.6 流式循环重写把 `textSent`（已外发正文，0.9.4 里
是字符串）改成了数字下标 `textSent = safeEnd`，但收尾处三处仍按字符串用：

- `finalText.startsWith(textSent)` → `startsWith("123")` 恒假 → **纯文本回复必抛
  STREAM_REWRITE，整轮作废、游标不前进**（会话续不上的直接原因）；
- `stripProtocolText(textSent)` → 正文块 text = `String(下标)`（助手文本变数字）；
- `finalText.slice(textSent.length)` → `slice(undefined)` = `slice(0)`，整段正文重发。

## 修复（lib/index.js + lib/agent-preset.js）

1. `textSent` 恢复字符串语义（保留 0.9.6 单调边界逻辑）。
2. `proseLimit` 首选分支从 `recognizedCall`（要求工具名已到）放宽为
   `rest.transport`——名字在参数分片里后到，`<tool_call>{"mcp_action"` 会先漏进
   正文；名字不匹配工具表时不开调用块，JSON 配平后游标越过，最终仍送达。
3. `findProtocolStart` 补「```json 围栏 + `{"name","arguments"}`（无 mcp_action，
   真机第二轮高频形状）」的 transport 判定，与 `parseAgentReply` 的 fenceRe 对齐。
4. `end.text` 为空（网页部分断流）时按已流出增量收尾，不误判空回复。

护栏：`test/stream-tail.test.mjs` 六项（不抛 STREAM_REWRITE / 正文块=散文原文 /
围栏形状不泄漏 / `5 < 10` 结尾不截断 / 断流按增量收尾 / 增量与块内容一致）。
