# 事件：修复中文对话 token 估算失真（字符数/4 → CJK/ASCII 混权）

## 背景
- 用户反复抱怨"网页端生成速度和估算有很大区别"。核查 index.js 的 estimateTokens = ceil(字符数/4) —— 对中文严重低估：汉字≈0.7–1 token/字，却被按 1/4 计（低估 2.8–4 倍），导致中文对话的 usage/进度显示与实际消费差距大。这正是"估算 vs 实际"的一个真实来源，而非标底偏差。

## 执行过程

[2026-09-07] 抽成纯函数并改估算模型
- 技术: estimateTokens 移到 lib/metrics.js 为纯函数；按 CJK（汉/日/韩，正则 \\p{Script=...}）≈0.7 tok、ASCII ≈0.25 tok 计价，末尾 +10% 安全余量，空串=0、非空≥1。
- 操作: lib/metrics.js 新增 estimateTokens；lib/index.js 移除本地定义并 import；test/metrics.test.mjs 增 5 项（空串、中文不低估、英文合理、最小1、混合计价）。
- 功能: 中文 usage 估算贴近真实，消除中文对话"估算与实测"系统性差距。

[2026-09-07] 验证
- 技术: node --test 全量 19 项全过（含新增）；node -e 对比：中文句 "本项目依赖安全性审查完成，未发现硬编码凭据。" 旧=6 新=16（~2.7×），英文句 旧7→新8（基本不变，合理）。
- 操作: 静态检查 + 单测 + 数值对比。
- 功能: 中文不再被低估数倍；英文行为几乎不变；零回归。

## 结论
- ✅ 移除中文 token 估算的系统性低估，回应用户"估算和实际区别"抱怨的一个真实根因；估算逻辑现为可单测纯函数，供 harness 进度/用量展示。
- ⚠️ 真正精确需真实 tokenizer（不可随意调用），当前为有据近似 + 安全余量。
- ⏭️ harness 侧把 usage 与「已用/剩余」展示接本估算即收益；跨平台/多站点仍需对应真实环境。
