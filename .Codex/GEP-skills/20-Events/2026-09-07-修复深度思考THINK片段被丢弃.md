# 事件：修复深度思考 fragments 的 THINK 内容被静默丢弃

## 背景
- 用户早期反复抱怨「深度思考没接好 / 网页一直思考但看得浅」。真机专家模式能出正文（RESPONSE 保留），但思考过程是否回传从未被断言。
- 用新单测（THINK + reasoning_* 两条护栏）核查时发现真实 bug：decoder.js `readFragment` 的 `content` 仅对 `type==='RESPONSE'` 保留，把 THINK/THINKING 片段的 content 清成 ''。于是 `if (f.type==='THINK' && f.content)` 恒为 false → fragments 数组里的深度思考被静默丢弃（只有独立 `reasoning_*` op 那条路径能触发 onThink）。注释 line 11 本写明 fragments 存 THINK/RESPONSE，与实现不自洽。

## 执行过程

[2026-09-07] 定位
- 技术: 新增单测「THINK 片段经 onThink 暴露且不污染正文」首先 FAIL，expected true got false——正是该路径 content 被 normalize 置空。
- 操作: 只读+单测定位 lib/decoder.js readFragment。

[2026-09-07] 修复
- 技术: readFragment 的 content 保留集合扩为 {RESPONSE, THINK, THINKING}（js Set），使 fragments 里的思考内容不再被清空；ON: consumeResponse 的 `else if (f.type==='THINK' && f.content)` 分支随即生效 onThink 暴露。
- 操作: lib/decoder.js readFragment + 类型守卫注释。

[2026-09-07] 验证
- 技术: 全量 node --test 22/22 过（regression 含新增 THINK fragments / reasoning_* 两道护栏；metrics / parse / mirror 无回归）。
- 操作: node --check + node --test。
- 功能: 深度思考可回传；正文不被思考污染；真实保障「思考看了不浅」。

## 结论
- ✅ 移除 fragments 深度思考静默丢弃的 bug，思考可经 onThink 单独回传；新增两道单测护栏防回归。
- ⚠️ reasoning_* 独立 op 路径本就正常，本次是 fragments 数组形态下的思考丢失。
- ⏭️ 在真实专家模式会话里复核 onThink 回传的思考文本（可后续纳入 real-verify 断言）。
