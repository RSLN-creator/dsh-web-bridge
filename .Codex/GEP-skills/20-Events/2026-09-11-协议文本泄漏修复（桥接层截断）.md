# 2026-09-11 协议文本泄漏：在桥接层截断，而非显示层折叠

[2026-09-11] 协议文本不再进助手文本 | 回退 0.9.1–0.9.3 显示层折叠（git stash，可恢复）、
新增 `findProtocolStart()` / `stripProtocolText()` / `normalizeDsml()`（lib/agent-preset.js）、
流式边界探测改用前者（lib/index.js）、真机夹具 + test/protocol-leak.test.mjs（9 项） | 0.9.0 -> 0.9.4，已 pack 并装入 web profile。

## 现象

用户界面里，助手回复显示成：

```
I'll start by inspecting the project state.
<tool_call>…整段协议 JSON/XML…
```

即**协议原文作为正文段落出现在对话流里**，既占屏幕又打断阅读。

## 真因：不是渲染层，是两套形态知识

会话 8e9c538a 的转录里，assistant/message 存的就是整段协议原文（已固化为
`test/fixtures/leaked-dsml-reply.txt`）。关键证据：同一段文本，

- `parseAgentReply` **解析正常**（它带 DSML 归一化），所以工具照常执行、任务没断；
- 流式那句行内 `marker()` **认不出**（只认半角标签 / ``` 围栏 / `**Calling:` / 裸 `{`），
  恒返回 -1，于是协议原文被当正文一路 `text-delta` 发出去、写进会话。

真机形态是全角竖线包起来的 DSML 标记（`｜DSML｜`，U+FF5C）。复现证据：
对夹具调用旧 `marker()` 得 `-1`，对归一化后的文本则正常命中。

## 为什么显示层折叠救不了它

0.9.1–0.9.3 把折叠做在客户端插件的 DOM 层，入口是 `querySelectorAll('pre')`——
**只扫 `<pre>` 代码块**。而泄漏出来的是正文段落，不是 `<pre>`，根本扫不到。
更关键的是层选错了：桥接层本来就有一次丢掉它的机会（发往界面之前），
显示层是第二道防线且当时是漏的。

0.9.1 更早还错在把脚本注入网页镜像——那改的是站点界面，不是 DSH 的回复显示。

## 修法（A 方案：桥接层截断）

`lib/agent-preset.js` 新增三个导出，把「哪些形态算协议」收敛到一处：

- `normalizeDsml(text)`：DSML 前缀归一（全角/半角竖线、丢开头 `<`）。
  `parseAgentReply` 改为调用它，不再内联一份正则——两处漂移正是本次事故的根因。
- `findProtocolStart(text)`：协议起点 + 工具名 + transport 判定。流式循环改用它，
  协议文本从此不进 `text-delta`。
- `stripProtocolText(text)`：下游兜底，保证写进会话的助手文本是散文。

`lib/index.js`：删掉旧的行内 `marker`、`suffix`/`candidate`/`transport` 三行，
边界探测走 `findProtocolStart`；工具调用轮的 text block 收尾走 `stripProtocolText`。

## 边界：工具闭环一字不改

解析仍吃原文——`parseAgentReply(finalText)` 的调用点没动，只截断「发往界面」的那一侧。
回归里显式锁住这一点：同一段真机文本，**界面拿散文、解析拿完整调用**同时成立。

## 环境坑（写给下一次）

**DSH 会把工具参数里的 DSML 字面量当协议注入剥离掉**，所以在 write/命令里直接写
`|DSML|` 或全角版本，会导致文件被截断或内容损坏（本轮踩了三次：SyntaxError、
362 字节截断、以及一次假的「探测/解析漂移」）。测试文件里一律用
`String.fromCharCode(0xff5c)` 程序化构造，绝不写字面量。

另：本沙箱 `node --test <file>` 会 `spawn EPERM`，直接 `node <file>` 跑；
`dsh plugin add` 要写 profile 目录，需提权（danger-full-access）。
