# 事件：修复 webcode 模型选择"没有可选模型" + 多模型

## 背景
用户报告 dsh-webcode-bridge 在 DSH 模型选择器里"模型的选择没有提供"。
排查真实 DSH 环境（profiles/web）、dsh-llm 契约、官方参照 opencode2dsh 后定位根因。

## 执行过程
1. 观察：日志 `webcode-restart-out.log` 显示 provider "webcode" 已注册、relay 正常、
   会话多轮可对话，但每轮 `chars` 极小——网页模型几乎不产出工具调用 JSON（对应"没分开没被识别"）。
2. 定位模型选择根因：
   - 对照 `@deepseek-ai/dsh-llm`：模型选择器实时读 `adapter.listModels`；
   - 对照 opencode2dsh adapter 模式：仅 `registerAdapter` 即入选择器；
   - webcode 却同时 `registerConfigurableProviders` + `registerAdapter`，造成双注册。
3. 修改 `package/dsh-webcode-bridge/lib/index.js`：
   - 删掉 `registerConfigurableProviders`，改纯 adapter 注册；
   - 新增 `WEB_MODELS`（标准对话 / 深度思考两个真实可选项），listModels 返回多模型；
   - resolveModel 校验未知模型并抛错；
   - 按 modelId 注入模式头（modeHint）到首轮/增量 prompt；
   - 工具调用 id 带会话前缀，便于追踪。
4. 更新 `test/run-m1.js` 断言（纯 adapter 注册 + 多模型 catalog），`node test/run-m1.js` 全绿 PASS。
5. bump 0.3.1，`npm pack`；把 profiles/web 依赖改为 file:...0.3.1.tgz；
   `npm install --legacy-peer-deps` 完成安装（2m）。

## 结论
- ✅ 修好模型选择：纯 adapter 注册 + 多模型 listModels/resolveModel。
- ✅ 门禁 M1 PASS，新 tgz 已装入 DSH web profile。
- ⏭️ 待用户重启 DSH 后在模型选择器实际验证是否出现
  "DeepSeek Web（标准对话 / 深度思考）"。
- ⚠️ 网页模型非 agent 模型的"工具调用不稳定"是架构性限制，列为后续 Phase。
