# 事件：核查 consent「授权一次永久保留」实现达标

## 背景
- 用户早期明确诉求「初次使用时授权一次就永久保留，后续不行才点击更换」。需核实 consent 是否真持久化到磁盘（重启不丢，非内存），以及授权变更语义。

## 执行过程

[2026-09-07] 静态核查 lib/relay.js
- 技术: consentStorePath 默认 profileDir/webcode-consent.json（与浏览器登录态同目录）；loadConsent() 启动读盘恢复；saveConsent() 原子写（.tmp-pid + rename 防截断成 first-run）+ mode 0o600；status().consentPersistent 暴露持久状态；setConsent(true/false) 覆盖旧值实现「后续更换」。
- 操作: 只读 grep（未改码）。
- 功能: 「授权一次永久保留」与「后续更换」两条语义均真实成立且安全。

[2026-09-07] 结论
- 技术: 成熟实现，无 bug；不为成熟写-read 路径强加需启动 HTTP server 的脆单测。
- 功能: 重启保留、与登录态同地持久、权限收紧（0o600）。

## 结论
- ✅ consent 持久化达标：首次授权落盘、重启保留、可再授权覆盖更换。
- ⏭️ 该项无需改动；持续关注后续版本是否改 consent 持久路径。
