# 2026-09-10 DeepSeek 新版 UI 适配 + 长跑调用形状六修（0.7.3）

[2026-09-10] 用户报告 chat.deepseek.com 改版（新模型 + 新界面），网页桥真机不可用（MODEL_UI_CHANGED）。三项诉求：审查方法不再被老代码淹没；真实审查 DeepSeek 网页长跑可行性；只改 DeepSeek 相关代码、提交 git 等反馈。

## 一、改版事实（真机取证，非二手结论）

新增探针 `test-mock/real-probe-19-newui.mjs`（只读 DOM + 一次发送）、`real-probe-20-newui-facts.mjs`（带图/按钮/开关/会话 URL）：

- 新版 UI **没有模型 pill**，输入框附近只剩「深度思考 / 智能搜索」两个 `aria-pressed` 开关；
- 首条消息 `model_type:"default"`，模式差异只在 `thinking_enabled`（点开关，下一条 POST 即随之变）；
- 带图发送 = `default` + `ref_file_ids`（识图不再单独占 model_type，回复实测读到图里的 HELLO）；
- 续聊消息 `model_type:null`（网页「沿用会话模型」）、`thinking_enabled` 仍逐条发送；
- 会话 URL 仍是 `/a/chat/s/<id>`；发送按钮 svg path 与旧契约一致；深度思考开关跨会话保留（三跑初始值 true/false/false 都出现过）。

证据落盘 `doc/research/deepseek-newui-2026-09-10.md`（用户提供的 probe19 Console 原文一并归并入档，根目录 probe19.txt 删除）。

## 二、驱动与契约适配（只动 DeepSeek 路径）

- `lib/browser-driver.js`：新增 `detectDeepSeekUi()`（classic 三 pill / unified 统一 UI，缓存 dsUi，换页失效）；unified 下 flash/deepseek 只拉「深度思考」开关（关/开），vision 走带图路由；开关定位不到 → `MODEL_UI_CHANGED` 附输入框可点项诊断。发送后核验从「只看非空 model_type」升级为契约期望元数据全量比对：unified 必查 `thinking_enabled`；`model_type` 缺失/null 视为网页沿用会话模型；取不到请求体本身即失败。
- `lib/metrics.js` 新增 `MODEL_TYPES_BY_UI` 与 `expectedRequestMetadata`；`lib/contract.js` 暴露期望（含 UI 代际参数）；`lib/providers.js` 展示名对齐两代 UI（labels DOM 契约不动）。
- `test-mock/real-verify.mjs`（pnpm doctor）：按 UI 代际取期望，unified 下 vision 判据=回复确实读到图（HELLO）。

## 三、长跑暴露的六种调用形状漂移（`lib/agent-preset.js`）

真机马拉松连跑七次抓到六种「看着像调用、解析器漏掉」的真实漂移：混合壳（invoke 体内裸 JSON）、新版 DSML 类型属性（`<parameter name="x" string="true">`）、JSON 包装壳（`<invoke name="tool_call">{完整调用对象}`）、参数包装壳（name/arguments 参数）、标签名漏 JSON、属性区漏 JSON。另修「同一调用多路径匹配重复入账」，probe-17 增「收束文本仍含调用记号即 FAIL」护栏。回放旧轨迹证实：修复前不仅丢畸形调用，普通一轮里 3 个 read 也只记 1 个。
