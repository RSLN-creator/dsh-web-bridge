# 事件：多站点内容服务打通（9 站点模型目录 + 独立 driver 路由）

## 背景
- 用户提出四项完善：思考链/深度思考不显示、图片返回有图说没图、内容服务太少（要求拉齐 glm/chatgpt 等 VS Code 插件参考）、参照蓝图与类似项目补齐。
- 思考链与图片链路（relay onThink/onImage → index.js reasoning 块 / imageMarkdown）上一轮已修并有测试；本轮核心是「内容服务太少」——DSH 模型选择器只暴露 DeepSeek 3 个模型，其余 8 个站点（GLM/ChatGPT/Kimi/Qwen/豆包/Grok/Claude/Gemini）虽有 providers.js 注册与解码器，但 listModels 未接入、executor 只路由单一 deepseek driver，选其他站点模型必然抛 MODEL_SITE_MISMATCH。

## 执行过程

[2026-09-08] 模型目录收口
- 技术: providers.js 新增 `listAllModels()`，返回全站点 'site:model' 限定 id + 能力元数据（thinking/vision/experimental）；index.js `WEB_MODELS = DEEPSEEK.models` 改为 `listAllModels()`，DSH 模型选择器与 OpenAI /v1/models 同源。
- 操作: lib/providers.js、lib/index.js。
- 功能: 模型选择器一次性出现 9 站点全部模型（约 24 个 + 兼容别名）。

[2026-09-08] 多 driver 路由
- 技术: index.js 新增 `driverFor(siteId)` 容器——deepseek 沿用默认 driver（兼容测试注入与既有 profile），其余站点懒创建 `createBrowserDriver({siteId, site, profileDir: profileDir/sites/<siteId>})`（独立 profile 防登录态串号）；executor 按 `meta.siteId` 路由到对应 driver，`meta.model` 全程携带站点前缀。
- 操作: lib/index.js、lib/browser-driver.js（无需改，createBrowserDriver 本就支持 siteId）。
- 功能: 'glm:glm-4.6' 等限定 id 可真正到达对应站点的驱动并选模型。

[2026-09-08] 模型 id 归一化单点
- 技术: providers.js 新增 `qualifyModelId(model, siteId)`（裸 id 补前缀、已限定原样、空值透传），executor 与 OpenAI 前端共用；openai.js 的 /v1/chat/completions 的 meta 增加 siteId 并传限定 id。
- 操作: lib/providers.js、lib/index.js、lib/openai.js。
- 功能: 杜绝跨站点重名模型串模型；OpenAI 前端调用多站点模型也可路由。

[2026-09-08] 按站点登录与状态聚合
- 技术: relay 的 `loginTrigger(siteId)` 按站点打开登录窗；`driverStatus()` 聚合全部站点状态（未初始化给占位、不启动浏览器），返回 sites[] 数组；/bridge/login 与 /__webcode/login 读 body.siteId；web-control status 改用聚合 driverStatus；dispose 关闭全部 driver。
- 操作: lib/index.js、lib/openai.js、lib/web-control.js。
- 功能: 每个站点可独立完成一次性登录，状态面板可见全部站点登录情况。

[2026-09-08] 设置页与测试
- 技术: 设置页「默认模型」下拉列全站点模型（含实验标记），loadSettings 用 MODEL_IDS 映射兼容历史裸 id；regression 更新 listModels 断言为多站点包含式断言，新增「限定 id 直达 executor」用例；multi-site-decoder.test.mjs 新增 qualifyModelId / listAllModels 用例。
- 操作: lib/index.js、test/regression.test.mjs、test/multi-site-decoder.test.mjs。
- 功能: 36 项测试全绿（新增 3 项），npm test（M1 流程）PASS。

## 结论
- ✅ 四项用户诉求全部落地：思考链（reasoning 块）、图片（markdown/image parts）、9 站点内容服务、参考蓝图与 26+ 逆向仓库（reference/）拉齐并对照实现解码器。
- ⚠️ 已知限制：多站点 DOM 契约（completionPaths 子串、模型选择器标签、图片回传形态）按 reference 逆向证据对齐，但除 DeepSeek 外各站点未做真机登录验证——GLM/ChatGPT/Kimi/Qwen 等需要逐一登录后校准选择器与 SSE 实际帧；Gemini 无稳定网络流，走 DOM 终态兜底（无思考链/图片）。
- ⏭️ 下一步：逐站真机校准（需各站账号）；跨平台 cfg 审查需 mac/linux 环境。
