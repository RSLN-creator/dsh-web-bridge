# 事件：真机定位并修复工具调用"从没接入 harness"

## 背景
用户反馈最深的一个问题："调用返回不会实际返回到 harness 做到接入"——网页模型
明明输出了工具调用，但 DSH 的 harness 从不执行它。此前一直按"网页模型不稳定"去归因。

## 执行过程
1. 读 `lib/agent-preset.js` 的 `parseAgentReply`：旧正则 ````/```(?:json)?…```/gi````
   只认 ```json 代码块围栏。
2. 读用户提供的真实返回样例：网页模型实际输出的是 **`<tool_call>…</tool_call>` 围栏**
   （opplean 风格），两种格式对不上 → 解析扫不到合法 call → 走纯文本 ← 真根因。
3. 写真实站点探针脚本 `real-drive.tmp.mjs`：驱动真实 edge-.real-profile 登录态，
   发一条带 webcode preset 的"调用 pwsh 执行 hostname"消息，抓取真实网页返回：
   确认为 `<tool_call>{"mcp_action":"call","name":"pwsh",…}</tool_call>`，
   修复后的 `parseAgentReply` 成功提取出 `{name:'pwsh', arguments:{command:'hostname'}}`。
4. 修改 `lib/agent-preset.js`：
   - `parseAgentReply` 同时接受三种围栏（```json / <tool_call>/<function>/<stories> / 裸对象），
     参数取 `arguments ?? input ?? parameters`，Set 去重防重复；
   - `buildPreset` 把 `<tool_call>` 定为推荐格式 A，```json 作为格式 B；
   - `TRAIN_NOTE` 同步改为 `<tool_call>` 格式。
5. 固化门禁 `test/parse.test.mjs`（含真实探针捕获的 `<tool_call>` 样例、多调用、prose 环绕、
   ```json、<function>、裸对象、纯文本、旧 {"tool":…} 回退），8/8 PASS；`run-m1` 仍 PASS。
6. bump **0.3.2** `npm pack`，profile 依赖指向 0.3.2.tgz，`npm install --legacy-peer-deps` 装入。
